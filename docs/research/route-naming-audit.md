# Route naming audit

Research date: 2026-10-03. Code read at `26a5715f` on main, after today's two renames (`7eec44fa` page addresses, `1125b4cf` API routers). Nothing was changed.

**How it was read.** Every route file under `apps/web/src/routes` (79 files, 77 addresses in `routeTree.gen.ts`), the English title of each page in `packages/i18n/src/messages/en.ts` (written `en.ts:<line>` below), the menu in `apps/web/src/components/shell/navigation.ts`, `CONTEXT.md`, ADRs 0009, 0013 and 0014, and the places an address leaves the code: the manifest, the service worker, push messages and printed papers. The API was listed by loading `appRouter` and walking it: 52 router keys, 403 procedures. The sources were read in their current published form, linked inline and listed at the end.

**Marks.** _keep_, _rename_, _move_ (same name, new parent), _merge_, _restructure_. "The source says" means the source's own words. "Recommendation" means mine.

---

## The question, and the answer

The Owner asked that all the routes be checked properly for enterprise readiness, naming `/farm`, `/milk`, `/home`, `/feed` and `/people`.

**Answer.** Today's renames got the spelling right. Every page address is lowercase ASCII, hyphenated and English, which is what GOV.UK, Zalando and Microsoft ask for. Collections are plural, and mass nouns (`/milk`, `/money`) are singular, as AIP-122 allows. Three problems are left.

1. **`/admin` groups pages by who may open them, not by what they are.** W3C names that as the classic way URIs break: "Access". The glossary also says to avoid "Admin" for the Owner and the Manager. The grouping has already gone wrong once: the audit log was opened to everybody but still sits under `/admin`, behind an exception in the layout guard. Recommendation: dissolve `/admin`. `/admin/feed` becomes `/feed` beside `/milk`, and `/admin/people` becomes `/people`.
2. **Several pages and their routers still use different words for the same thing.** `/farm` is served by `home.owner`. `/work` is served by `instances`, a name AIP-190 singles out as problematic. `/admin/herd` is "Sheds & pens". `/registration-certificate` is titled "Inspector View".
3. **Procedure verbs have no shared rule.** `open` means three different things in three routers. "Bring back" is spelled two ways, and one of them (`restore`) collides with the glossary's Restore Drill. There are three spellings of "the caller's own" (`me`, `mine`, `my…`).

`/animals/$tagNumber` is safe to keep. A Tag Number never changes, and a Re-tag keeps it, both in the glossary and in the code. Only four old addresses need a permanent redirect, because they are the only ones held outside the code: `/today`, `/login`, `/device` and `/portal/login`.

## 1. Principles, and where each applies

oRPC is RPC, not REST. Its wire path `/api/rpc/<router>/<procedure>` is built from object keys, never typed by a person, and never bookmarked. So the page-address sources (GOV.UK, W3C) govern pages. Google's AIPs govern router and procedure names, since AIP-121 says resource-oriented design "is a pattern for specifying RPC APIs". The REST guides (Zalando, Microsoft) are used for pages only by analogy, and for RPC only where they say something about naming.

**Do not apply.** [Zalando #135](https://opensource.zalando.com/restful-api-guidelines/#135) ("SHOULD not use /api as base path") is written for an API-only service. Here `/api` is what keeps the API apart from the pages on one origin. The service worker relies on it (`apps/web/public/sw.js:100`), and so does the Investor address's allowlist (`apps/web/src/lib/two-addresses.ts:16-17`). Zalando's snake_case property rule (#118) is about JSON fields and is out of scope here.

**How the conventions map onto files (TanStack Router).** `_authenticated` is a pathless layout ("Route segments with the `_` prefix are considered to be pathless layout routes"). `route.tsx` is "a route file at the directory's path", `index` matches the parent exactly, and `$name` is a parameter. All of this is already used correctly. The one quirk is deliberate: the Portal Preview tree lives at `routes/investors/$investorId/portal-preview/`, outside `_authenticated`. That lets it draw the portal's frame, not the app shell (`portal-preview/route.tsx:26-29`). Its addresses still nest under `/investors/$investorId`.

## 3. Tabs: path or query

Eighteen pages keep a tab in `?tab=`. **The sources do not require a path:** a query is part of the URI too, so these are already bookmarkable and shareable (TanStack search-params guide). What the sources do give is a division of labor: paths name things (P6, Zalando #143) and queries filter (P8, Zalando #137).

**Recommendation.** A tab that is a different kind of record, usually with its own router, becomes a child route. A tab that filters one list stays a query. Do it first for the pages other screens already link into, because those links show the tab is a destination in its own right.

## 4. `/animals/$tagNumber`: tag or id?

The question assumed that a Re-tag changes the number in the address. **It does not.**

- **The glossary.** A Tag Number is "an Animal's permanent identity … never reused, unchanged if the Animal changes Side" (CONTEXT.md:41). A Re-tag replaces the Ear Tag "with one carrying the same Tag Number", and the glossary says to avoid "Re-numbering (which never happens)" (CONTEXT.md:43, :47).
- **The code agrees.** `animals.retag` inserts a `retag` row and never updates `animal.tag_number` (`packages/api/src/routers/animals.ts:1214-1250`). No correction touches it (`packages/api/src/corrections/*`). A Tag Number is unique per Farm (`packages/db/src/schema/herd.ts:194`) and always has the form `D-0001` or `F-0001` (`packages/domain/src/tag-number.ts:9`). The opening register refuses anything else (`packages/api/src/herd-store.ts:96-101`). It is URL-safe under Zalando #228 and readable under Microsoft's readability rule.
- **Nothing printed encodes it as an address.** The Animal Passport and the transport card print the tag as text (`packages/domain/src/papers.ts:167`, `:286`). The only QR code anywhere is the Welcome Letter's, and it carries the portal address (`apps/web/src/components/investors/welcome-letter.tsx:9`, `:156`). A death push opens `/animals/<tag>` (`packages/api/src/push.ts:53-55`).

**Recommendation: keep the tag.** It is stable, it is what a person reads off the animal, and the sources prefer it to a UUID (P9). Two small fixes:

- **Canonical case.** The server upper-cases the parameter (`animals.ts:652`), so `/animals/d-0001` and `/animals/D-0001` show the same page: an alias under P7. Redirect lower case to upper case in the route's `beforeLoad`. Microsoft allows the case-insensitive match. AIP-122 asks for one canonical name.
- **A second Farm.** A Tag Number is unique only within its Farm. ADR 0013 keeps one Farm per server. If that ever changes, put the farm in the host, as Microsoft's [URL pattern](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md#http-url-pattern) puts the tenant first (`https://<tenant>.<region>.<service>…`), not in the path. Every path here then survives unchanged.

## 7. Procedure verbs across routers

Of the 403 procedures, `set…` (31), `correct…` (17), `record…` (14) and `list` (19) are already used the same way everywhere. Keep those. The rest disagree with each other as follows.

1. **`open` means three different things.**
   - `reviewQueue.open` is a read: the items still open (`review-queue.ts:17`).
   - `vetCases.open` is a create: it calls a Vet in about one animal (`vet-cases.ts:82-86`).
   - `ventures.open` is a create: it writes a new Venture (`ventures/lifecycle.ts:350-356`).

   The two creates are the domain's own words (a Venture is Open, ADR 0011). The read is an adjective. Recommendation: `reviewQueue.open` → `reviewQueue.list`.

2. **Making something new has five verbs.**
   - `add`: `breeds.add` (`breeds.ts:110`), `drugs.add` (`drugs.ts:361`), `money.addCategory` (`money-entries.ts:218`), `feed.addItem`, `farmAccounts.add`, `notifiableDiseases.add`.
   - `create`: `herd.createShed` (`herd.ts:69`), `sops.create` (`sops.ts:365`).
   - `register`: `animals.register` (`animals.ts:885`).
   - `enter`: `money.enter` (`money-entries.ts:440`).
   - `record`: for events, e.g. `investors.record` (`investors.ts:388`).

   AIP-133's word is `Create`. Recommendation: `create` for something the farm defines (a Breed, a Category, a Shed), and `record` for something that happened, which the glossary already says throughout ("the recorded hand-over"). That retires `add`. `animals.register` and `money.enter` can stay, because both are the farm's words for that act.

3. **The inverse of `retire` is spelled two ways.**
   - `bringBack` (7): `drugs.ts:592`, `notifiable-diseases.ts:258`, `investors.ts:494`, `feed.ts:383` (`bringBackItem`), `bringBackRation`, `money-entries.ts:422` (`bringBackCategory`).
   - `restore` (2): `breeds.ts:225`, `sops.ts:865`.

   AIP-164's analogue is Undelete, but retiring is not deleting. `restore` also collides with the glossary's **Restore Drill**, a backup restore (CONTEXT.md:444). Recommendation: `bringBack` everywhere.

4. **The caller's own has three spellings.**
   - `me`: `people.me` (`people.ts:143`), `portal.me`, `portalPreview.me`.
   - `mine`: `alerts.mine` (`alerts.ts:43`), `diagnoses.mine` (`diagnoses.ts:343`), `vetCases.mine` (`vet-cases.ts:174`).
   - `my…`: `money.myFees` (`money.ts:344`), `portal.myRequests` (`portal.ts:153`).

   Recommendation: `me` for the caller's own record (a singleton, AIP-156) and `mine` for the caller's items. Then `portal.myRequests` → `portal.requests` (everything in `portal` is the caller's), and `money.myFees` → `money.mine`, or `vetFees.mine` if Vet Fees get a router.

5. **Reads named after the screen, not the data.** `returns.page` (`returns.ts:33`), `registrationCertificate.view` (`registration-certificate.ts:314`) and `fattening.board` (`fattening.ts:30`). W3C's warning about subject applies here too: screens change "surprisingly fast". Recommendation: name what comes back. These need new words, so check CONTEXT.md before choosing them. `fattening.board` may stay if "board" is adopted as the term.
6. **Prepositions, and one concept spelled four ways.**
   - "For one Animal": `milk.forAnimal` (`milk.ts:281`), `prescriptions.forAnimal` (`prescriptions.ts:260`), `vetCases.forAnimal` (`vet-cases.ts:54`), `costs.ofAnimal` (`costs.ts:19`), `returns.animal` (`returns.ts:61`).
   - Other prepositions: `animals.byTag` (`animals.ts:647`), `home.byMonth`, `costs.bySide`, `receivables.ofBuyer` (`receivables.ts:76`), `stock.onTheScale`, `ventures.takeOutOfPortal`, `ventures.planAgainstActual`, `portal.agreeToOffer`, `instances.closeAsMissed`, `farm.startWithStandard`, `investors.inviteToPortal`.

   AIP-136 and AIP-140 say no prepositions, and that a filter is a request field (AIP-132). Recommendation, cheapest first: one spelling for one concept (`forAnimal` in all five places, AIP-140 Uniformity). Then `byTag` → `get`. Leave the act names with prepositions alone: they read as the farm speaks, and AIP's rule is a "must" only inside Google.

7. **Adjective and time reads.** `backups.recent` (`backups.ts:21`), `observations.recent` (`observations.ts:16`), `diagnoses.waiting`, `instances.today` (`instances.ts:256`), `eidDates.next` (`eid-dates.ts:38`), `farm.current` (`farm.ts:518`), `devices.current` (`devices.ts:215`), `ventures.running`. The `recent` pair are plain lists → `list`. `current` and `next` are singletons and read well. Leave them.
8. **Push.** `listen` / `stopListening` (`push.ts:57`, `:98`) → `subscribe` / `unsubscribe`, as in section 6.

**Proposed rule, for the CONTEXT.md or AGENTS.md conventions** (my wording):

- A router is the plural camelCase noun of its glossary term, or the singular for a mass noun or a singleton.
- `list` and `get` read the router's own resource. Any other read is the noun for what comes back, with no preposition and no screen word.
- `create` makes something the farm defines. `record` writes down something that happened. `correct…` puts it right. `retire` and `bringBack` take it out of use and back.
- `me` is the caller's record. `mine` is the caller's items.
- Every other act is a VerbNoun in the farm's words (AIP-136), never a CRUD word in disguise (Microsoft actions-no-actions-for-crud).

## 9. Open questions for the Owner

The sources do not settle these. Each has a recommendation.

1. **`/registration-certificate` or `/inspector-view`?** You chose `/registration-certificate` today. The page's title, its menu label, the glossary (CONTEXT.md:458) and its router's own comment all say Inspector View, and the certificate is a small part of it. GOV.UK says to "align with the title". W3C's "Access" rule would leave the reader ("inspector") out, which points to `/registers` instead. But "register" already means three things here: the Register (CONTEXT.md:460), `animals.register` and the opening register. **Recommendation:** `/inspector-view` and `inspectorView`.
2. **`/portal/offers` or `/portal/open-ventures`?** Every portal page says it "is not a public offer" (`en.ts:132`). ADR 0009 turned down `invest.` because the address read as an invitation. The glossary avoids "Offer" alone (CONTEXT.md:331), and the router already says `openVentures`. **Recommendation:** `/portal/open-ventures`, and ask the lawyer whether it matters, since they approved the portal "as built".
3. **Move `/farm` (the Owner's overview) to `/overview`, and put the farm's identity and parameters at `/farm`?** That reuses an address. **Recommendation:** yes, now. Nothing outside the code holds `/farm` (section 5). After launch it could not be done.
4. **Keep `/home` for the Manager's day?** Its title is "Today on the farm", and "today" already names the redirect `/today`, the work list's label and a menu group. **Recommendation:** keep `/home`. It is the start page of whoever runs the farm, and reusing `/today` would break the home-screen apps that `/today` is kept for.
5. **Dissolve `/admin`?** **Recommendation:** yes. Each page then needs its own `beforeLoad: onlyFor("runsTheFarm")` (`apps/web/src/lib/guard.ts:11`), which is how every other guarded page already works. The menu already says "a filter for finding things, never the permission itself" (`navigation.ts:67-72`).
6. **Turn tabs into paths: all of them, or only the ones linked to?** **Recommendation:** the nine pages in section 3 that others link into, now. The rest when each page is next touched.
7. **`/device`, `/admin/devices` and router `devices` become `/shed-phone`, `/shed-phones` and `shedPhones`?** **Recommendation:** the pages yes. The router only if the device-token code is being touched anyway, because "device" also names the session behind it (`packages/api/src/device-headers.ts`).
8. **`instances` becomes `work` or `sopInstances`?** `work` matches the page. `sopInstances` matches the glossary noun. **Recommendation:** `work`, as AIP-190 asks for the specific name the reader uses.
9. **Will anyone outside the farm ever call the API?** If so, it gets its own versioned, resource-shaped surface. oRPC's OpenAPI handler is already wired, but only outside production (`routes/api/rpc/$.ts:95-103`). The RPC paths stay the app's own. **Recommendation:** not before a farm asks.
10. **What word means feed coming into the store, bought or harvested?** The `arrivals` tab and `stock.arrivals` need a glossary term before they become a path (section 3). **Recommendation:** none chosen here. CONTEXT.md first.

## 10. How to apply

**Order.** Each step is one branch and one merge. Each leaves the app whole.

1. **The small ones.**
   - `/today` sends 308 (`statusCode: 308` on its `redirect`).
   - `public/robots.txt` says `Disallow: /`. Today its empty `Disallow:` allows every crawler (RFC 9309 §2.2.2: with no matching rule "the URI is allowed"), on both addresses (`two-addresses.ts:15`). It is not a security control (RFC 9309 §3).
   - Drop the dead `/rpc` check in `sw.js:100`.
   - Remove `healthCheck` and its two tests.
   - Remove the `/ventures?statements=` redirect.
2. **Dissolve `/admin`.**
   - Move the twelve pages to the top level, renaming `herd` → `sheds` and `devices` → `shed-phones`.
   - Add an `onlyFor` guard to each, since `admin/route.tsx` guarded them all. Leave `/audit` open to everyone, as now.
   - Move `/farm` → `/overview`, then `/admin/farm` → `/farm`. Fix `LANDING` and `BOTTOM_BAR` (`navigation.ts:342-415`) and the menu.
   - The compiler finds every typed `<Link>`. Grep only the strings it cannot see: `"/admin/audit"` in `admin/route.tsx:8`, which goes with the file.
   - An open browser tab keeps the old route tree until it reloads.
3. **Doors.**
   - `/login` → `/sign-in` and `/portal/login` → `/portal/sign-in`, each leaving a 308 file behind.
   - `/device` → `/shed-phone` with a 308. Update `_authenticated/route.tsx:69`, `:83`.
   - Fold `/dashboard` into `/` (17 references, including `lib/guard.ts:35` and the sign-in forms).
   - `docs/runbooks/deploy.md:250` names `/portal/login`. The runbooks carry your uncommitted work, so that line is yours to change.
4. **Tabs to paths** (section 3). Each tabbed page becomes a folder with a `route.tsx` layout holding the header and tab bar, an `index.tsx` for the first tab, and one file per tab. Then switch the `search={{ tab }}` links listed in section 3 to the new `to`.
5. **Routers.**
   - Split `home` into `home`, `overview` and `monthlyReport`.
   - Rename `instances` → `work`, `trips` → `buyingTrips` and `herd` → `sheds`, moving `deaths` and `calfLosses`. Rename `devices` → `shedPhones` if question 7 says so, and `registrationCertificate` → `inspectorView` if question 1 does.
   - **Do not rename `portal`, `people.me` or `language` without changing all four of** `two-addresses.ts:17`, `query-cache.ts:96-99`, `two-addresses.test.ts:40-42` and `deploy.md:226`.
   - The Outbox sends by entry kind, so `sync.batch` and the queued entries are unaffected (commit `1125b4cf`).
6. **Procedure verbs** (section 7), one router per commit. The compiler finds every caller.

**Caches, the service worker and the manifests.**

- **Persisted query cache.** Queries are kept under their router path. Rename `CACHE_KEY` (`apps/web/src/lib/query-cache.ts:31`) in the same commit as any router rename, as `1125b4cf` did. Otherwise a phone draws a fortnight-old answer under a key nothing reads.
- **Service worker.** Bump `SHELL` (`sw.js:12`, now `openfarm-shell-v4`) in step 2. An offline phone otherwise opens a cached shell whose router has no `/overview`.
- **Manifests.** `start_url` stays `/work` and `/portal`, so neither manifest changes. `SHELL_FILES` (`sw.js:15`) does not change either.
- **Push.** The URLs stay `/work`, `/work/$instanceId` and `/animals/$tagNumber`, so `push.ts:44-56` does not change.

**Tests to update.**

- `apps/web/src/lib/two-addresses.test.ts:29-56`: its lists name `/portal/login`, `/login`, `/dashboard` and the portal RPC paths.
- `packages/api/src/routers/index.test.ts:11` and `visiting-scope.test.ts:66`: `healthCheck`.
